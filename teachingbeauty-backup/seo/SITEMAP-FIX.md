# サーチコンソールの「インデックス未登録」を減らす（2026-09-26）

クライアントから、サーチコンソールの「ページがインデックスに登録されなかった理由」に
404・リダイレクト・重複・noindex・クロール済み未登録が並んでいるとの連絡があった。

## 原因

ふたつ。どちらもサイトの表示とは無関係で、Google に渡している案内が古かっただけ。

### 1. 旧ホームページビルダー時代の `/sitemap.xml` がサーバーに残っていた

中身は移行前のもので、48件のうち

- 9件が旧ドメイン `http://teachingbeauty.main.jp/...`（現ドメインへ 301）
- 1件が `https://www.teachingbeauty.jp/index.html`（`/` へ 301）
- 1件が `funin aen.html`（スペース入り。旧サイトの打ち間違いで、実在しない）

`robots.txt` もこの古いファイルを指していたため、Google は毎回ここを読みに来ていた。
「リダイレクトがあります」「見つかりませんでした（404）」「重複しています」は、
いずれもこの住所録を辿った結果を報告していたもの。

### 2. WordPress が自動で作るページをサイトマップに載せていた

`wp-sitemap.xml` に以下が入っていた。旧サイトには無かったページ。

- `/hello-world/`（WordPress インストール時の初期投稿）
- `/category/uncategorized/`
- `/author/admin/`

中身の薄いページとして扱われ、「クロール済み - インデックス未登録」の対象になる。

## 対応

### テーマ側（`teachingbeauty-theme/functions.php`）

- `wp_sitemaps_post_types` を固定ページだけに絞る
- `wp_sitemaps_taxonomies` を空にする（カテゴリー・タグを外す）
- `wp_sitemaps_add_provider` で投稿者一覧を外す
- 固定ページ以外（投稿・アーカイブ・検索結果・404）に `noindex` を出す
- フィードはトップへ 301（旧サイトに無いため）

固定ページ39枚の出力は変わらない。ローカル環境で全ページを取得して
変更前後を比較し、1バイトの差も無いことを確認済み。

### サーバー側

1. `/sitemap.xml` を削除
2. `/robots.txt` を `seo/robots.txt` に差し替え（Sitemap 行を `wp-sitemap.xml` に）

`/sitemap.xml` を消すと WordPress が `/wp-sitemap.xml` へ 301 を返すようになるため、
サーチコンソールに登録済みの `sitemap.xml` もそのまま生きる。ローカルで確認済み。

### サーチコンソール

「サイトマップ」から `wp-sitemap.xml` を送信する。
古い `sitemap.xml` の登録は残しておいてよい（301 で新しい方へ繋がる）。

## 反映の目安

数日〜2週間。その間は画面に古い数字が残る。検索順位・表示への影響は無い。

## 残っているもの

`/hello-world/` の初期投稿は noindex にしただけで、記事自体は残っている。
管理画面の「投稿」からゴミ箱へ入れれば消える。急ぎではない。

## 適用

`teachingbeauty-backup/fix-sitemap.local.ps1`（FTP パスワードを含むため Git 管理外）を実行する。
アップロード・削除・検証まで通しで行う。
