# iPhone で行頭が揃わない（2026-09-26）

クライアントから「左詰めが合っていない」との指摘。Meniere.html のスクリーンショット（iPhone / Safari）で、
`【完治するの？】` に続く各行の頭が1文字分ずれていた。

## 原因

旧サイトの HTML はホームページビルダーが吐いたもので、行頭に半角スペースが10個ほど入っている。

```html
<br>
          まず、発症から2〜3年以内に施術を開始する事により…
```

HTML は空白をまとめるので、この10個は1個分になる。
Chrome は「強制改行の直後の空白」を捨てる（CSS Text の規定どおり）ので消えるが、
Safari は捨てずに1文字分描画する。そのため iPhone だけ行頭がずれる。

移行で生じたものではなく、旧サイトの時点から同じ。Chrome で検証していたため見落としていた。
WebKit は Playwright が取得できず（ダウンロードがタイムアウト）、自動テストに載せられていなかった。

## 対応

`<br>` の直後の空白そのものを本文から取り除いた。空白が無くなれば、どのブラウザでも揃う。
文中の空白と `&nbsp;` には触れていない。全39ページ・9,495 箇所。

適用は `cutover/tb-fix-br-space.php`。直す前の本文は postmeta（`_tb_br_space_backup`）に控えてあり、
`?restore=1` で元に戻せる。

## 途中で見つけた落とし穴

最初は `wp_update_post()` で書き込んでいたが、ローカル検証で2つの事故を踏んだ。

1. **料金の「\45,000」からバックスラッシュ（¥記号）が消えた**
   `wp_update_post()` は渡された値を `wp_unslash()` する。
2. **`<font size="6" color="#480a17" <br>` のような閉じ忘れタグが書き換わり、タグが文字として表示された**
   ログインしていない状態で走るため KSES が働く。index.html の 55 行目に実在する。

どちらも `$wpdb->update()` で直接書くことで解消。既存の `tb-fix-content.php` と同じやり方。

## 検証

ローカルに本番同等の環境（WordPress 7.1 / SQLite / 本テーマ / 39ページ / 元サイトの画像・CSS）を作り、
修正前後を比較した。

- `<br>` 直後が空白で始まるテキスト節点: 4,917 → 0
- 画面幅 1280px：全39ページ、スクリーンショットがピクセル単位で一致。文字の位置も全一致
- 画面幅 390px（スマホ）：全39ページで文字の位置が一致
- 最大ページ newpage10（高さ 72,369px）の全要素 2,711 個の位置・大きさが一致
- 適用 → 復元の往復で、39ページすべて元の内容とハッシュ一致（バックスラッシュ含む）

newpage10 のスマホ幅で 254 ピクセルの差が出たが、これは本文の右外側（横スクロール領域）の背景で、
**修正前の状態で2回撮っても同じ差が出る**。描画のブレであって今回の変更とは無関係。

測定にあたり、テーマのフェードイン演出を止めている。止めないと同じ状態でも22ページで差が出て比較にならない。
